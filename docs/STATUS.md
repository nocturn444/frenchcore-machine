## 4. What the owner needs to do or listen to

Things only the owner can do in GitHub (the agent cannot). Steps in Spanish are in the 0.1.0 security audit, section 10:

- Branch protection of `main` (Settings, Branches): it exists, but its list of required checks is empty and admins can bypass it. Add the required checks `Format check`, `Linux`, `macOS` and `Windows`, and tick "Do not allow bypassing the above settings". Do **not** tick "Require review from Code Owners" (see section 3).
- A tag ruleset for `v*` (Settings, Rules, Rulesets, New tag ruleset): restrict deletions and block force pushes, so a published version tag cannot be moved.
- Enable "Private vulnerability reporting" (Settings, Security), because `SECURITY.md` sends reporters there. Also turn on Dependabot alerts and Dependabot security updates.
- Check Settings, Actions, General: workflow permissions on "Read repository contents and packages permissions", and "Allow GitHub Actions to create and approve pull requests" unticked.
- Decide what to do with the personal email in the first commit (pending with the security review; rewriting the history also means re-creating or withdrawing the 0.1.0 tag and release).
- Optionally, edit the notes of the 0.1.0 release with the known limitations (the text is in `.github/release-notes.md`).
- When the 0.1.1 pull request is merged: start the release (`docs/RELEASING.md`, version `v0.1.1`), check the draft and publish it.

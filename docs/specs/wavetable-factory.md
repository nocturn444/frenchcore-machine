# Spec: Factory wavetables and wavetable selection

- Status: Implemented (Phase 4, first part; the sound decisions in section 7 were taken by the agent on the product owner's instruction to decide and keep going, and are waiting for their ears)
- Owner: nocturn4 (product), implemented by agent session
- Related: [oscillator-wavetable](oscillator-wavetable.md), [ADR 0008](../decisions/0008-wavetable-selection-and-publishing.md), [ARCHITECTURE §4.2](../ARCHITECTURE.md), [MVP_SCOPE](../MVP_SCOPE.md)

## 1. What it does for the user

Each oscillator gets a **Wavetable** choice. Instead of always playing a pure sine, an oscillator can play one of nine built-in waveforms made for kicks. A wavetable is a stack of waveforms; **Position** slides through the stack, so one knob goes from a clean sine to a harder, more distorted shape.

The nine factory wavetables, in menu order (the order never changes, new ones are only added at the end):

| # | Name | Frames | What it sounds like |
|---|---|---|---|
| 1 | Sine | 1 | The clean sine of the first versions. The default. |
| 2 | Soft Triangle | 1 | A little brighter than a sine, still round. |
| 3 | Warm Drive | 8 | Sine to a soft-saturated sine (tanh drive from 1 to 6). |
| 4 | Hard Clip | 8 | Sine to a hard-clipped sine, close to a square at the end. |
| 5 | Wave Fold | 8 | Sine folding back on itself, more folds towards the end. |
| 6 | Odd Stack | 8 | Sine to a square-like wave by adding odd harmonics one by one. |
| 7 | Saw Rise | 8 | Sine to a saw-like wave by adding all harmonics. |
| 8 | Hardcore Punch | 12 | Asymmetric, heavily driven sine: the aggressive "hardcore" bite. |
| 9 | Rumble Core | 16 | Biased and overdriven sine with a lot of even harmonics, for gritty body. |

All of them are generated by code in this project (original, no sample material), so they are free to redistribute under the project licence.

Behaviour:

- The table applies to the oscillator it is chosen on; Osc 1 and Osc 2 can use different ones.
- All tables are normalised so their loudest point is the same as the sine's. A hard or folded wave still sounds louder than the sine at the same Level because it has more energy; lower **Level** to taste.
- Changing the wavetable while a kick sounds changes the waveform at the next audio block. It can click; it is meant for setting up the sound, not for automation tricks.
- Wavetables are band-limited like the sine (no harsh aliasing at the top of the pitch drop).

The saved value is the entry number. The list is append-only so old projects keep their sound.

## 4. DSP / implementation approach

- `fcm::dsp::FactoryWavetables` (in `fcm_dsp`, no JUCE state): `count()`, `name(i)`, `makeFrames(i)` returns the raw frames (`numFrames * 2048` floats) and `build(i)` returns the band-limited `WavetableData`. Generation is deterministic.
- Each frame is made by evaluating a formula for one cycle of 2048 samples (the formulas are in the code, with the table names above): `tanh` saturation, clipping, `sin(k sin x)` folding, and additive harmonic series. Then the mean is removed (no DC offset) and the frame is scaled so its peak is exactly 1.
- `fcm::core::WavetableSelector` (one per oscillator, in `fcm_core`): listens to `oscN.wavetable`, and on the message thread builds the table and publishes it through a `PublishedPointer<WavetableData>` ([ADR 0008](../decisions/0008-wavetable-selection-and-publishing.md)). The first table is published during construction, so the engine has it when playback starts.
- `Engine::setWavetableSources(osc1, osc2)` hands the publishers to the engine. Once per block it acquires both and gives them to the voice, which also sets them on the fading copies of the previous kick. Without a publisher, or before the first publish, the engine plays its built-in sine.
- Real-time: nothing allocates or locks on the audio thread; the table is built and freed away from it.

## 5. Tests

Catch2:

- `FactoryWavetables` (`fcm_dsp_tests`): there are 9 tables with unique, non-empty names in the documented order; every table has 1 to 256 frames and the documented frame count; all samples are finite; every frame has a peak of 1 within 1e-5 and a mean of 0 within 1e-5; generation is deterministic; every table builds into a `WavetableData`; the Sine table equals a sine within 1e-6; frames of the morphing tables differ from each other (the first and last frame are not identical).
- Oscillator with every factory table at 55 Hz, 440 Hz and 4 kHz: finite output, peak at most 1.2, and for the harmonic tables no aliasing above -60 dB measured with the FFT at 4 kHz (a control with a naive saw proves the measurement can fail).
- Engine: with a published table the kick uses it (output differs from the default sine and is finite); publishing a new table between blocks switches it at the next block; swapping the table many times during playback with retriggers every few samples gives finite output and no use of freed memory (run under the address sanitizer once); without a source the engine plays the sine.
- `PublishedPointer`: unchanged.
- `WavetableSelector` (`fcm_core_tests`): the initial table is published at construction; changing the parameter publishes the table of the new entry (after the message loop runs); an out-of-range saved value (state loading clamps it) selects a valid table; the order of the choice list is guarded (names and order).
- Parameters: `osc1.wavetable` and `osc2.wavetable` exist, are choices, default to 0, and are in the released-ID guard.

Manual check: choose each table on Osc 1 in the Standalone, play the auto-play loop and move Position.

## 7. Open questions and decisions taken

Taken by the agent (the product owner asked for decisions to be made and written down, and to be told what to listen to):

1. Nine tables, in the order above; the names and morphs are first choices. The product owner should listen to each in the Standalone and say which to drop, rename or replace (the list is append-only once released, so changes are cheapest now).
2. Tables are peak-normalised, not loudness-matched.
3. Switching the table mid-kick may click and is not smoothed.
4. Position keeps its meaning: 0 is the first frame, 1 the last.
